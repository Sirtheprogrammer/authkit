AuthKit Documentation

AuthKit is an open-source, stateless authentication and user management service designed to be embedded, self-hosted, and reused across any stack with zero friction.

Core Principles

  • 100% Stateless Verification: Signs standard RS256/HS256 JWT tokens and exposes an RFC 7517 JWKS endpoint. Downstream APIs verify signatures without querying the database.
  • Multi-Database Agnostic: Plug in SQLite, PostgreSQL, MySQL, or MongoDB. Auto-migrations run on boot.
  • Custom Dynamic Schema: Store and validate whatever custom attributes your application demands without manual DDL migrations.
  • Universal OAuth: Built-in Google Cloud OAuth2, GitHub OAuth, and direct Firebase ID token validation.
  • Zero-Dependency Binary: Built as a single Go binary embedding its own documentation, landing page, and admin interface.
  • AI First: Built-in Model Context Protocol (MCP) server for Claude Desktop, Cursor, and agentic workflows.

Quickstart Guide

Deploy AuthKit locally or on your server in under 60 seconds.

Option 1: One-Line Install Script

Bash
curl -fsSL https://raw.githubusercontent.com/sirtheprogrammer/authkit/main/scripts/install.sh | bash

Option 2: Docker / Docker Compose

docker-compose.yml
version: '3.8'
services:
  authkit:
    image: authkit/authkit:latest
    ports:
      - "8080:8080"
    environment:
      - DB_TYPE=sqlite
      - DB_FILE=/data/authkit.db
      - BASE_URL=http://localhost:8080
      - JWT_ALGORITHM=RS256
    volumes:
      - authkit_data:/data

volumes:
  authkit_data:

Option 3: Run Binary Directly

Terminal
# Run interactive configuration wizard
./authkit init

# Start server
./authkit serve

Stateless JWT & JWKS Verification

Unlike legacy session managers that require database lookups on every single incoming HTTP request, AuthKit uses asymmetric cryptographic signatures:

  1. User logs in via POST /api/v1/auth/login.
  2. AuthKit signs a JWT access token with an RSA private key. The token payload contains sub (User ID), email, role, and metadata.
  3. Your downstream services fetch the public keys once from GET /.well-known/jwks.json and cache them.
  4. Every downstream microservice verifies tokens locally with zero network hops.
OIDC Discovery Document
GET /.well-known/openid-configuration

{
  "issuer": "authkit",
  "jwks_uri": "http://localhost:8080/.well-known/jwks.json",
  "response_types_supported": ["token", "id_token"],
  "claims_supported": ["sub", "email", "role", "metadata", "iss", "exp"]
}

Multi-Database Configuration

AuthKit supports four enterprise databases out of the box:

1. SQLite (Default / Zero-Config)

Embedded, pure Go driver. No C compiler or external server needed.

Environment
DB_TYPE=sqlite
DB_FILE=./authkit.db

2. PostgreSQL

Uses connection pooling and native JSONB columns for dynamic custom schema attributes.

Environment
DB_TYPE=postgres
DATABASE_URL=postgres://user:password@localhost:5432/authkit?sslmode=disable

3. MySQL

Uses InnoDB engine with native JSON columns and UTF-8 multibyte encoding.

Environment
DB_TYPE=mysql
DATABASE_URL=root:password@tcp(localhost:3306)/authkit?parseTime=true

4. MongoDB

Native BSON storage with dynamic document mapping and automatic index provisioning.

Environment
DB_TYPE=mongodb
DATABASE_URL=mongodb://localhost:27017/authkit

Dynamic Custom Schema

Configure custom attributes in authkit.yaml. AuthKit validates types, lengths, regular expressions, and allowed values automatically on signup and updates.

authkit.yaml
schema:
  strict: false # if true, disallows undeclared keys
  fields:
    - name: phone
      type: string
      pattern: '^\+?[1-9]\d{1,14}$'
      required: false
    - name: company
      type: string
      max_length: 100
      required: true
    - name: tier
      type: string
      allowed_values: ["free", "pro", "enterprise"]
      default: "free"
    - name: age
      type: number
      min: 18

OAuth: Google & GitHub

To enable OAuth providers, supply client credentials in environment variables or authkit.yaml:

Environment
# Google Cloud Console
GOOGLE_CLIENT_ID=your-google-client-id.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=your-google-client-secret
GOOGLE_REDIRECT_URL=http://localhost:8080/api/v1/auth/oauth/google/callback

# GitHub Developer Settings
GITHUB_CLIENT_ID=your-github-client-id
GITHUB_CLIENT_SECRET=your-github-client-secret
GITHUB_REDIRECT_URL=http://localhost:8080/api/v1/auth/oauth/github/callback

Firebase Project Integration

Allow clients using the Firebase SDK (Web, iOS, Android, Flutter) to authenticate directly into AuthKit:

Environment
FIREBASE_PROJECT_ID=my-firebase-project-id

Client application workflow:

Client JavaScript
import { getAuth } from 'firebase/auth';

const auth = getAuth();
const idToken = await auth.currentUser.getIdToken();

// Exchange Firebase token for AuthKit session
const res = await fetch('http://localhost:8080/api/v1/auth/firebase/verify', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ id_token: idToken }),
});
const authKitSession = await res.json();

Model Context Protocol (MCP) AI Server

AuthKit implements the Model Context Protocol (MCP) JSON-RPC 2.0 specification over Stdio and HTTP (POST /mcp). Connect Claude Desktop or Cursor directly:

claude_desktop_config.json
{
  "mcpServers": {
    "authkit": {
      "command": "/usr/local/bin/authkit",
      "args": ["mcp"]
    }
  }
}

Supported MCP Tools

  • authkit_list_users: Search and query users with role and status filters.
  • authkit_get_user: Retrieve user attributes and custom schema metadata.
  • authkit_create_user: Provision users with custom fields.
  • authkit_update_user: Modify roles, status, or metadata.
  • authkit_ban_user: Suspend users and invalidate sessions instantly.
  • authkit_delete_user: Remove user records.
  • authkit_inspect_token: Statelessly verify and decode JWT tokens.
  • authkit_send_password_reset: Trigger password reset emails.
  • authkit_get_system_stats: Fetch database status and metrics.

REST API Reference

Authentication Endpoints
POST   /api/v1/auth/signup               # Register new user
POST   /api/v1/auth/login                # Authenticate and obtain JWT
POST   /api/v1/auth/refresh              # Rotate refresh token
POST   /api/v1/auth/logout               # Revoke session
GET    /api/v1/auth/me                   # Get profile (Requires Auth)
PUT    /api/v1/auth/me                   # Update custom fields (Requires Auth)

POST   /api/v1/auth/password/forgot      # Request password reset
POST   /api/v1/auth/password/reset       # Set new password with token/OTP
POST   /api/v1/auth/verify-email/confirm # Verify email with token/OTP
POST   /api/v1/auth/verify-email/resend  # Resend verification email

GET    /api/v1/auth/oauth/providers      # List enabled OAuth providers
GET    /api/v1/auth/oauth/{provider}     # Initiate OAuth redirect
GET    /api/v1/auth/oauth/{provider}/callback # Process callback
POST   /api/v1/auth/firebase/verify      # Verify Firebase ID token
Admin & System Endpoints
GET    /api/v1/users                     # List users (Admin)
POST   /api/v1/users                     # Create user (Admin)
GET    /api/v1/users/{id}                # Get user by ID (Admin)
PUT    /api/v1/users/{id}                # Update user (Admin)
DELETE /api/v1/users/{id}                # Delete user (Admin)

GET    /.well-known/jwks.json            # RFC 7517 Public Key Set
GET    /.well-known/openid-configuration # RFC 8414 OIDC Discovery
GET    /health                           # System health check
POST   /mcp                              # Model Context Protocol JSON-RPC
